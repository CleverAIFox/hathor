## D-0151. 합계만 박은 못은 어디가 달라졌는지 못 알려준다

> **갱신됨 — D-0152.** 부류별 못이 **한 판에 자리를 짚었다** —
> `test_bge_m3_lyrics_encoder.py:130`이며 `transformers`가 깔린 기기에서만 보인다.

- **갱신**: D-0150 — 부류 표를 찍게 했으나 **합계를 박고 있었다.**

- **배경**: D-0150이 못을 66으로 다시 박았고 **다음 기기에서 67이 나왔다.**
  표가 `assignment 1`을 보여줬고 **내 사본에는 없는 부류였다.**

### 표가 절반을 풀었다

D-0150이 부류 표를 안 찍게 했으면 *"67과 66"*만 보고 또 추측했을 것이다.
**표 덕분에 `assignment`라는 것까지는 한 번에 나왔다.**

**그런데 어느 줄인지는 여전히 몰랐다.** 기기를 못 보니 파일도 행도 알 수 없고,
한 판 더 물어야 한다.

- **후보**: 무엇을 못 박을 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **부류별로 박고 어긋난 부류의 줄을 찍는다** | **채택** |
  | (2) 합계를 박고 표만 찍는다 | **기각.** D-0150의 상태이며 한 판이 더 든다 |
  | (3) `assignment`도 환경 의존으로 뺀다 | **기각.** 진짜 오류 부류다. 빼면 놓친다 |

- **선택**: **(1).**

    타입 오류가 67건으로 못 박은 66건과 다르다.
      arg-type              19 / 19
      assignment             1 / 0     ←늘
      ...
        tests/unit/test_x.py:10: error: 대입 형이 안 맞는다  [assignment]

**어긋난 순간 어느 줄을 봐야 하는지가 나온다.**

### 세 결정에 걸쳐 같은 것을 배웠다

| | 무엇을 잘못 셌나 |
|---|---|
| D-0148 | `.venv`를 찌꺼기로 셌다 |
| D-0150 | 환경 의존 오류를 래칫에 넣었다 |
| **D-0151** | **합계만 박아 어느 부류인지 못 봤다** |

셋 다 **세는 것이 성긴 탓**이고, 성긴 수는 그 수를 보고 한 판단까지 성기게 만든다.
**고칠 때마다 한 칸씩 더 촘촘해졌다.**

- **결과**:
  - `PINNED`이 부류별 표다. `--update`가 정렬해 다시 쓴다.
  - 어긋난 부류의 **실제 줄을 찍는다.**
  - 검사 3건 추가.

### 남기는 것

- **`assignment` 한 건이 왜 기기에서만 나는지 모른다.** 다음 `make check`가
  그 줄을 찍어 주면 거기서 판단한다. **추측해서 미리 고치지 않는다** (GR-0.5).
- **`--allow-growth`가 부류별로도 필요할 수 있다.** 지금은 아무 부류나 늘면 막는다.

재현
    python3 tools/check_test_types.py

강제자  `core/tests/unit/test_test_types.py`

## D-0152. 배선이 돌았다 — 실측 탐침을 세운다

> **갱신됨 — D-0154.** 이 탐침이 20곡을 읽었고 **분석이 안 선다는 것**을 냈다.

> **갱신됨 — D-0153.** 이 탐침이 **첫 실행에서 빈손이었다.** D-0069가 도구에는 안
> 걸려 있어 `core/var/ingest`를 보고 있었다.

- **갱신**: D-0151 — `assignment` 한 건의 자리가 드러났고 고쳤다.

- **배경**: `ingest onsets --limit 20`이 돌았다. **20곡 · 홉 0.01초 · 실패 0.**
  D-0145의 배선이 실물에서 처음 섰다.

### 표가 한 판에 끝냈다

D-0151이 어긋난 부류의 줄까지 찍게 했고 **다음 실행에서 바로 나왔다.**

    tests/unit/test_bge_m3_lyrics_encoder.py:130: error: Incompatible types in
    assignment (expression has type "SimpleNamespace", variable has type Module)

`transformers`가 깔린 기기에서만 실제 타입이 보인다. **`type: ignore`를 달면 그쪽은
사라지고 깔리지 않은 쪽은 `unused-ignore`가 되는데 그것은 이미 안 세는 부류다**
(D-0150). **양쪽이 66으로 맞는다.**

D-0148 → D-0150 → D-0151 → 여기까지 **네 판에 걸쳐 세는 것을 촘촘하게 만들었고,
마지막 한 건이 한 판에 끝났다.**

### 탐침은 판정하지 않는다

`tools/probe_onsets.py`가 곡별 빠르기 · 격차 · 배수 격차 · 박 안 위상을 낸다.
**분포를 낼 뿐이며 무엇을 제품에 쓸지는 보고 나서 결정 기록으로 정한다** — 탐침이
판정하면 그 자리에서 값이 생긴다 (D-0058).

`probe_chord_rhythm`과 같은 모양이다. **정본은 도메인 서비스 하나이고 탐침은 그것을
부른다** (D-0123).

### 볼 것 넷

| | 무엇을 말해주나 |
|---|---|
| 빠르기 분포 | **`--tempo` 기본값 96이 얼마나 틀렸는가** |
| 격차 | 낮으면 박을 못 고른 것이다 |
| 배수 격차 | 낮으면 **사람도 갈릴 자리다** (D-0054) |
| 박 안 위상 | **반주 리듬의 재료다.** 고르면 정박에 안 몰린다는 뜻이다 |

- **결과**:
  - `tools/probe_onsets.py`.
  - `test_bge_m3_lyrics_encoder.py:130`에 `type: ignore`와 사유.

### 남기는 것

- **아직 20곡이다.** 1004곡 배치가 남았고, 20곡의 분포가 전체를 대표한다는 근거는
  없다.
- **박의 원점은 여전히 모른다** (D-0143). 위상 분포의 *모양*만 뜻이 있다.
- **합성에 없던 것이 실측에 있다** — 리버브 · 스윙 · 박자 변화. 탐침이 그것을
  어떻게 드러낼지는 보고 나서 안다.

재현
    cd core
    uv run python ../tools/probe_onsets.py --out var/ingest

강제자 없음 — 사유: 탐침이며 판정하지 않는다. 고정할 동작이 없다

## D-0153. 탐침이 빈손으로 돌아왔다 — D-0069가 도구에는 안 걸려 있었다

- **갱신**: D-0152 — 그 탐침이 첫 실행에서 아무것도 못 찾았다.

- **배경**: `ingest onsets`가 20곡을 `var/ingest/keys-0.01s.onsets`에 썼는데
  **탐침이 "포락선 폴더가 없다"고 했다.**

### 같은 `var/ingest`가 두 곳을 가리켰다

둘 다 `core/`에서 돌렸다.

| | `--out var/ingest`가 푼 곳 |
|---|---|
| `ingest onsets` (CLI) | `<저장소>/var/ingest` — **`resolve_path`가 푼다** (D-0069) |
| `probe_onsets` (도구) | `<저장소>/core/var/ingest` — **현재 디렉터리 기준** |

**D-0069는 CLI 인자에만 걸려 있었다.** `test_cli_contracts`가 `hathor.cli`의 파서를
훑어 `type=resolve_path`를 요구하는데 **`tools/`는 그 검사 밖이었다.**

D-0146이 검사마다 빼 둔 나무를 훑은 것과 **같은 부류이고 이번에는 계약 쪽이다.**

### 셋이 같았다

전수로 보니 경로 인자를 받는 도구가 넷이고 그중 **셋이 현재 디렉터리 기준**이었다.
`lyrics_exclusion_probe` · `lyrics_language_profile`은 저장소 루트에서 돌리는 것이
관행이라 **지금까지 맞았을 뿐이다.** `sync_artifacts`만 루트를 쓰고 있었다.

- **결과**:
  - 셋이 `ROOT` 기준으로 푼다. 절대 경로는 그대로 쓴다.
  - `test_cli_contracts`가 **`tools/`도 본다.** argparse를 실행 없이 들여다볼 수
    없어 **본문에 `ROOT`가 있는지로 본다** — 거칠지만 이 부류를 잡는다.

### 왜 조용했나

**빈손이 오류처럼 안 보인다.** 탐침은 *"폴더가 없다"*고 정확히 말했고 그 말이
맞았다 — **다른 폴더를 보고 있었다는 것만 안 말했다.** 경로를 함께 찍었으면 한눈에
보였을 것이고, 그래서 이제 폴더 이름을 첫 줄에 찍는다.

### 남기는 것

- **검사가 거칠다.** `ROOT`라는 글자가 있는지만 본다. 경로 인자를 받으면서 `ROOT`를
  다른 용도로 쓰는 도구가 생기면 통과한다. **더 촘촘하게 하려면 도구마다
  `build_parser()`를 노출해야 하고 그것은 열여섯 파일을 고치는 일이다.**
- **20곡 실측은 아직 못 봤다.** 탐침이 이제 제자리를 보므로 다음 판에 나온다.

재현
    cd core
    uv run python ../tools/probe_onsets.py

강제자  `core/tests/unit/test_cli_contracts.py`

## D-0154. 20곡 실측이 전곡 배치를 막았다 — 분석이 안 선다

> **갱신됨 — D-0155.** 짐작한 원인(드리프트)이 **틀렸다.** 추정은 잘 되고 있었고
> 연속 에너지가 위상을 뭉갰다.

- **갱신**: D-0143 · D-0144 — 합성에서 통한 것이 실측에서 안 통한다.

- **배경**: `ingest onsets --limit 20`의 산출물을 탐침으로 읽었다.

### 숫자 넷이 같은 말을 한다

| | 실측 | 뜻 |
|---|---|---|
| 박 안 위상 (평균) | `0.257 · 0.247 · 0.247 · 0.250` | **완전 균등** |
| 빠르기 중앙 | **69.9 BPM** | 가요 코퍼스에서 비정상 |
| 배수 격차 `< 0.10` | **12 / 20 (60%)** | 과반이 배수 모호 |
| 격차 중앙 | 0.02 | 1등과 2등 봉우리가 거의 같다 |

**위상 균등이 결정적이다.** D-0143이 합성에서 이 모양을 봤을 때가 **주기 오차로
위상이 뭉개진** 그 버그였다. 3~5분 곡은 400박이 넘고 **주기가 0.1%만 틀려도 끝에서
0.4박이 밀린다** — 합성 128박의 세 배 규모다.

### 합성이 못 담은 것

D-0143이 *"합성에는 리버브도 스윙도 박자 변화도 없다"*고 남겼다. **그 남긴 것이
그대로 값을 냈다.** 합성 12판은 빠르기가 고정이었고 실제 곡은 아니다.

**합성이 관문이라는 것은 맞았고, 관문을 지났다고 통과한 것이 아니라는 것도 맞았다.**

### 전곡 배치를 어떻게 할 것인가

- **후보**:
  | 안 | 판정 |
  |---|---|
  | (1) **포락선만 전곡 뽑고 분석은 보류** | **채택** |
  | (2) 전곡 뽑고 분석까지 돌린다 | **기각.** 못 쓰는 판정 1004개가 생긴다 |
  | (3) 분석이 설 때까지 추출도 멈춘다 | **기각.** 아래 |

- **선택**: **(1).** **포락선은 원자료이고 분석은 나중에 다시 돌린다.** 저장소가
  분리돼 있으므로(`.onsets`는 포락선만 담는다) 추출이 낭비가 아니다. 디코딩이 가장
  비싼 단계이고 그것만 한 번 해 두면 된다.

### 무엇이 나쁜지 아직 모른다

**포락선이 나쁜 것과 추정이 나쁜 것은 다르다.** 가르는 진단을 넣었다.

    uv run python ../tools/probe_onsets.py --diagnose 0

30초 구간마다 따로 재서 **값이 고르면 추정은 되고 위상만 밀린 것**이고
**들쭉날쭉하면 포락선이 나쁜 것**이다. 합성으로 확인했다 — 빠르기 고정 곡은
표준편차 **0.00**, 8% 흔들리는 곡은 **6.26**이었다.

- **결과**:
  - `probe_onsets --diagnose`. 포락선 선명도 · 곡 전체 추정 · 구간별 분포.
  - **전곡 배치는 포락선까지만.** PLAN §1에 적었다.

### 남기는 것

- **위상을 곡 전체로 재는 방법이 틀렸을 가능성이 크다.** 주기 하나로 나눗셈하는
  대신 박을 따라가야(beat tracking) 할 수 있다. **그것은 새 설계이며 진단 결과를
  보고 정한다.**
- **빠르기 중앙 69.9가 절반 오류인지 코퍼스 성질인지 모른다.** 발라드가 많으면
  70대가 이상하지 않다. **20곡으로는 못 가른다.**

재현
    cd core
    uv run python ../tools/probe_onsets.py --diagnose 0

강제자 없음 — 사유: 실측 판정이며 고정할 동작이 없다

## D-0155. 위상이 평평했던 것은 드리프트가 아니라 바닥이었다

> **갱신됨 — D-0156.** 이 고침이 **실측에서 안 통했다.** 바닥을 빼도 잔물결이
> 남았고 봉우리가 박보다 16.7배 촘촘했다.

- **갱신**: D-0154 — 그 결정이 짐작한 원인이 틀렸다.

- **배경**: `--diagnose 0`을 돌렸다. **진단이 짐작을 뒤집었다.**

### 추정은 아주 잘 되고 있었다

    30초 구간별 · 7구간
      5% 68.70 · 25% 68.88 · 중앙 68.95 · 75% 69.10 · 95% 179.12
      표준편차 24.12BPM

**표준편차 24.12는 오해다.** 일곱 중 **여섯이 68.70~69.10 안에 모여 있고**(폭
0.4BPM) 하나만 179로 튀었다 — 간주나 무박 구간일 것이다. **곡 전체 추정 68.91과도
0.04BPM 차이다.**

D-0154는 *"주기가 0.1%만 틀려도 끝에서 0.4박이 밀린다"*고 짐작했는데 **실측 오차는
0.06%이고 251박에서 0.15박이다. 그것으로는 안 뭉개진다.**

### 원인은 연속 에너지였다

합성에 바닥을 넣으니 그대로 재현됐다.

| 바닥 | 박 안 위상 |
|---|---|
| 없음 | `0.675 · 0.000 · 0.000 · 0.325` |
| 0.2 | `0.192 · 0.307 · 0.194 · 0.307` |

**실제 곡에는 노래와 지속음이 연속 에너지를 깔아 둔다.** `phase_profile`이 평균만
빼서 그 바닥이 **모든 위상에 고르게 들어갔다.**

**발음은 봉우리지 에너지가 아니다.**

- **후보**: 무엇을 셀 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **이웃보다 높은 칸만 센다** | **채택** |
  | (2) 문턱을 둬서 낮은 칸을 버린다 | **기각.** 문턱이 값이다 (D-0058) |
  | (3) 중앙값을 빼고 그대로 센다 | **기각.** 바닥이 줄 뿐 사라지지 않는다 |

- **선택**: **(1).** 문턱도 창도 없고 **중앙값 위 높이를 무게로 쓴다.**
  바닥 0.05에서 최대 위상이 `0.765`로 살아났다.

### 자기상관은 안 고쳤다

봉우리로 돌려도 **배수 오류는 안 고쳐진다** — 120BPM·바닥 0.2에서 원본도 봉우리도
60을 골랐다. 96과 140은 둘 다 맞는다. **120은 60이 정확한 半배수라 진짜로 모호하며
`octave_margin`이 이미 신고한다** (D-0143).

**안 고쳐지는 것을 고친 척하지 않는다.**

- **결과**:
  - `onset.peaks`. `phase_profile`이 봉우리만 센다.
  - 검사 5건. **바닥이 있어도 위상이 안 뭉개지는 것**을 고정했다.

### 남기는 것

- **실제 곡에서 아직 확인 못 했다.** 합성에서 고쳤고 20곡을 다시 읽어야 안다.
- **배수 오류는 그대로다.** 빠르기 중앙 69.9가 절반인지 코퍼스 성질인지도 그대로다.

## D-0156. 두 번 짐작하고 두 번 틀렸다 — 세 번째는 재고 고쳤다

- **갱신**: D-0155 — 그 고침이 실측에서 안 통했다.

- **배경**: D-0155가 봉우리만 세게 고쳤는데 **20곡 위상이 그대로였다** —
  `0.256 · 0.249 · 0.245 · 0.250`이고 고른 곡이 15에서 **16으로 늘었다.**

### 짐작 둘이 모두 틀렸다

| | 짐작한 원인 | 실측 |
|---|---|---|
| D-0154 | 주기 오차로 위상이 밀린다 | **아니다.** 7구간 중 6개가 0.4BPM 안 |
| D-0155 | 연속 에너지 바닥이 깔린다 | **부분만.** 고쳐도 그대로였다 |

**세 번째 짐작 대신 쟀다.** `--diagnose`에 봉우리 수와 간격을 넣었다.

    봉우리 5142개 (25.7%) · 간격(칸) 중앙 3.0
    박 하나가 50.0칸 · 봉우리 간격 중앙의 16.7배

**봉우리가 박보다 16.7배 촘촘했다.** 이웃만 보는 판정이 **잡음의 잔물결을 전부
발음으로 셌고**, 그것이 모든 위상에 고르게 들어갔다. 바닥을 빼도 잔물결은 남는다 —
**D-0155가 절반만 고친 이유다.**

- **후보**: 봉우리를 어떻게 성기게 할 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **보고할 해상도 한 칸에 하나** | **채택** |
  | (2) 높이 문턱을 둔다 | **기각.** 문턱이 값이다 (D-0058) |
  | (3) 평활 창을 키운다 | **기각.** 창 길이가 값이고 D-0103이 이미 겪었다 |

- **선택**: **(1).** `PHASE_BINS`가 이미 보고 눈금이므로 **새 값이 아니다.**
  칸 하나 안에서 가장 높은 것만 남긴다.

| 바닥 | 이전 위상 | 이후 |
|---|---|---|
| 0.1 | 평평 | **`0.779` · 0.092 · 0.096 · 0.032** |
| 정박+뒤박 | 갈리지 않음 | **`0.554` · 0.028 · **`0.398`** · 0.020** |

### 왜 두 번이나 틀렸나

**둘 다 합성에서 재현한 뒤 고쳤다.** 그런데 합성이 실제 곡의 성질을 하나씩만
담았다 — D-0154는 드리프트만, D-0155는 바닥만. **실제 곡은 둘 다에 잔물결까지
있었고, 그 셋째를 합성에 안 넣었으니 안 보였다.**

**고칠 곳을 합성으로 찾지 말고 실측에서 재야 했다.** `--diagnose`가 그 자리다.

- **결과**:
  - `peaks(envelope, apart=)`. `phase_profile`이 칸 절반만큼 떨어뜨린다.
  - `--diagnose`가 **봉우리 수 · 간격 · 박 대비 배수**를 찍는다.
  - 검사 4건 추가.

### 남기는 것

- **또 실측에서 확인해야 한다.** 합성에서 통했고 20곡은 아직 안 읽었다.
  **이번에도 안 통하면 합성을 더 고치지 말고 실측 진단을 더 넣는다.**
- **배수 오류와 빠르기 중앙 69.9는 그대로다.**

재현
    cd core
    uv run python ../tools/probe_onsets.py --diagnose 0

강제자  `core/tests/unit/test_onset.py`
