## D-0151. 합계만 박은 못은 어디가 달라졌는지 못 알려준다

> **갱신됨 — D-0152.** 부류별 못이 **한 판에 자리를 짚었다** —
> `test_bge_m3_lyrics_encoder.py:130`이며 `transformers`가 깔린 기기에서만 보인다.

- **갱신**: D-0150 — 부류 표를 찍게 했으나 **합계를 박고 있었다.**

- **배경**: D-0150이 못을 66으로 다시 박았고 **다음 기기에서 67이 나왔다.**
  표가 `assignment 1`을 보여줬고 **내 사본에는 없는 부류였다.**

### 표가 절반을 풀었다

D-0150이 부류 표를 안 찍게 했으면 *"67과 66"*만 보고 또 추측했을 것이다.
**표 덕분에 `assignment`라는 것까지는 한 번에 나왔다.**

**그런데 어느 줄인지는 여전히 몰랐다.** 기기를 못 보니 파일도 행도 알 수 없고,
한 판 더 물어야 한다.

- **후보**: 무엇을 못 박을 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **부류별로 박고 어긋난 부류의 줄을 찍는다** | **채택** |
  | (2) 합계를 박고 표만 찍는다 | **기각.** D-0150의 상태이며 한 판이 더 든다 |
  | (3) `assignment`도 환경 의존으로 뺀다 | **기각.** 진짜 오류 부류다. 빼면 놓친다 |

- **선택**: **(1).**

    타입 오류가 67건으로 못 박은 66건과 다르다.
      arg-type              19 / 19
      assignment             1 / 0     ←늘
      ...
        tests/unit/test_x.py:10: error: 대입 형이 안 맞는다  [assignment]

**어긋난 순간 어느 줄을 봐야 하는지가 나온다.**

### 세 결정에 걸쳐 같은 것을 배웠다

| | 무엇을 잘못 셌나 |
|---|---|
| D-0148 | `.venv`를 찌꺼기로 셌다 |
| D-0150 | 환경 의존 오류를 래칫에 넣었다 |
| **D-0151** | **합계만 박아 어느 부류인지 못 봤다** |

셋 다 **세는 것이 성긴 탓**이고, 성긴 수는 그 수를 보고 한 판단까지 성기게 만든다.
**고칠 때마다 한 칸씩 더 촘촘해졌다.**

- **결과**:
  - `PINNED`이 부류별 표다. `--update`가 정렬해 다시 쓴다.
  - 어긋난 부류의 **실제 줄을 찍는다.**
  - 검사 3건 추가.

### 남기는 것

- **`assignment` 한 건이 왜 기기에서만 나는지 모른다.** 다음 `make check`가
  그 줄을 찍어 주면 거기서 판단한다. **추측해서 미리 고치지 않는다** (GR-0.5).
- **`--allow-growth`가 부류별로도 필요할 수 있다.** 지금은 아무 부류나 늘면 막는다.

재현
    python3 tools/check_test_types.py

강제자  `core/tests/unit/test_test_types.py`

## D-0152. 배선이 돌았다 — 실측 탐침을 세운다

> **갱신됨 — D-0153.** 이 탐침이 **첫 실행에서 빈손이었다.** D-0069가 도구에는 안
> 걸려 있어 `core/var/ingest`를 보고 있었다.

- **갱신**: D-0151 — `assignment` 한 건의 자리가 드러났고 고쳤다.

- **배경**: `ingest onsets --limit 20`이 돌았다. **20곡 · 홉 0.01초 · 실패 0.**
  D-0145의 배선이 실물에서 처음 섰다.

### 표가 한 판에 끝냈다

D-0151이 어긋난 부류의 줄까지 찍게 했고 **다음 실행에서 바로 나왔다.**

    tests/unit/test_bge_m3_lyrics_encoder.py:130: error: Incompatible types in
    assignment (expression has type "SimpleNamespace", variable has type Module)

`transformers`가 깔린 기기에서만 실제 타입이 보인다. **`type: ignore`를 달면 그쪽은
사라지고 깔리지 않은 쪽은 `unused-ignore`가 되는데 그것은 이미 안 세는 부류다**
(D-0150). **양쪽이 66으로 맞는다.**

D-0148 → D-0150 → D-0151 → 여기까지 **네 판에 걸쳐 세는 것을 촘촘하게 만들었고,
마지막 한 건이 한 판에 끝났다.**

### 탐침은 판정하지 않는다

`tools/probe_onsets.py`가 곡별 빠르기 · 격차 · 배수 격차 · 박 안 위상을 낸다.
**분포를 낼 뿐이며 무엇을 제품에 쓸지는 보고 나서 결정 기록으로 정한다** — 탐침이
판정하면 그 자리에서 값이 생긴다 (D-0058).

`probe_chord_rhythm`과 같은 모양이다. **정본은 도메인 서비스 하나이고 탐침은 그것을
부른다** (D-0123).

### 볼 것 넷

| | 무엇을 말해주나 |
|---|---|
| 빠르기 분포 | **`--tempo` 기본값 96이 얼마나 틀렸는가** |
| 격차 | 낮으면 박을 못 고른 것이다 |
| 배수 격차 | 낮으면 **사람도 갈릴 자리다** (D-0054) |
| 박 안 위상 | **반주 리듬의 재료다.** 고르면 정박에 안 몰린다는 뜻이다 |

- **결과**:
  - `tools/probe_onsets.py`.
  - `test_bge_m3_lyrics_encoder.py:130`에 `type: ignore`와 사유.

### 남기는 것

- **아직 20곡이다.** 1004곡 배치가 남았고, 20곡의 분포가 전체를 대표한다는 근거는
  없다.
- **박의 원점은 여전히 모른다** (D-0143). 위상 분포의 *모양*만 뜻이 있다.
- **합성에 없던 것이 실측에 있다** — 리버브 · 스윙 · 박자 변화. 탐침이 그것을
  어떻게 드러낼지는 보고 나서 안다.

재현
    cd core
    uv run python ../tools/probe_onsets.py --out var/ingest

강제자 없음 — 사유: 탐침이며 판정하지 않는다. 고정할 동작이 없다

## D-0153. 탐침이 빈손으로 돌아왔다 — D-0069가 도구에는 안 걸려 있었다

- **갱신**: D-0152 — 그 탐침이 첫 실행에서 아무것도 못 찾았다.

- **배경**: `ingest onsets`가 20곡을 `var/ingest/keys-0.01s.onsets`에 썼는데
  **탐침이 "포락선 폴더가 없다"고 했다.**

### 같은 `var/ingest`가 두 곳을 가리켰다

둘 다 `core/`에서 돌렸다.

| | `--out var/ingest`가 푼 곳 |
|---|---|
| `ingest onsets` (CLI) | `<저장소>/var/ingest` — **`resolve_path`가 푼다** (D-0069) |
| `probe_onsets` (도구) | `<저장소>/core/var/ingest` — **현재 디렉터리 기준** |

**D-0069는 CLI 인자에만 걸려 있었다.** `test_cli_contracts`가 `hathor.cli`의 파서를
훑어 `type=resolve_path`를 요구하는데 **`tools/`는 그 검사 밖이었다.**

D-0146이 검사마다 빼 둔 나무를 훑은 것과 **같은 부류이고 이번에는 계약 쪽이다.**

### 셋이 같았다

전수로 보니 경로 인자를 받는 도구가 넷이고 그중 **셋이 현재 디렉터리 기준**이었다.
`lyrics_exclusion_probe` · `lyrics_language_profile`은 저장소 루트에서 돌리는 것이
관행이라 **지금까지 맞았을 뿐이다.** `sync_artifacts`만 루트를 쓰고 있었다.

- **결과**:
  - 셋이 `ROOT` 기준으로 푼다. 절대 경로는 그대로 쓴다.
  - `test_cli_contracts`가 **`tools/`도 본다.** argparse를 실행 없이 들여다볼 수
    없어 **본문에 `ROOT`가 있는지로 본다** — 거칠지만 이 부류를 잡는다.

### 왜 조용했나

**빈손이 오류처럼 안 보인다.** 탐침은 *"폴더가 없다"*고 정확히 말했고 그 말이
맞았다 — **다른 폴더를 보고 있었다는 것만 안 말했다.** 경로를 함께 찍었으면 한눈에
보였을 것이고, 그래서 이제 폴더 이름을 첫 줄에 찍는다.

### 남기는 것

- **검사가 거칠다.** `ROOT`라는 글자가 있는지만 본다. 경로 인자를 받으면서 `ROOT`를
  다른 용도로 쓰는 도구가 생기면 통과한다. **더 촘촘하게 하려면 도구마다
  `build_parser()`를 노출해야 하고 그것은 열여섯 파일을 고치는 일이다.**
- **20곡 실측은 아직 못 봤다.** 탐침이 이제 제자리를 보므로 다음 판에 나온다.

재현
    cd core
    uv run python ../tools/probe_onsets.py

강제자  `core/tests/unit/test_cli_contracts.py`
