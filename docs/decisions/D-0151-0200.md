## D-0151. 합계만 박은 못은 어디가 달라졌는지 못 알려준다

> **갱신됨 — D-0152.** 부류별 못이 **한 판에 자리를 짚었다** —
> `test_bge_m3_lyrics_encoder.py:130`이며 `transformers`가 깔린 기기에서만 보인다.

- **갱신**: D-0150 — 부류 표를 찍게 했으나 **합계를 박고 있었다.**

- **배경**: D-0150이 못을 66으로 다시 박았고 **다음 기기에서 67이 나왔다.**
  표가 `assignment 1`을 보여줬고 **내 사본에는 없는 부류였다.**

### 표가 절반을 풀었다

D-0150이 부류 표를 안 찍게 했으면 *"67과 66"*만 보고 또 추측했을 것이다.
**표 덕분에 `assignment`라는 것까지는 한 번에 나왔다.**

**그런데 어느 줄인지는 여전히 몰랐다.** 기기를 못 보니 파일도 행도 알 수 없고,
한 판 더 물어야 한다.

- **후보**: 무엇을 못 박을 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **부류별로 박고 어긋난 부류의 줄을 찍는다** | **채택** |
  | (2) 합계를 박고 표만 찍는다 | **기각.** D-0150의 상태이며 한 판이 더 든다 |
  | (3) `assignment`도 환경 의존으로 뺀다 | **기각.** 진짜 오류 부류다. 빼면 놓친다 |

- **선택**: **(1).**

    타입 오류가 67건으로 못 박은 66건과 다르다.
      arg-type              19 / 19
      assignment             1 / 0     ←늘
      ...
        tests/unit/test_x.py:10: error: 대입 형이 안 맞는다  [assignment]

**어긋난 순간 어느 줄을 봐야 하는지가 나온다.**

### 세 결정에 걸쳐 같은 것을 배웠다

| | 무엇을 잘못 셌나 |
|---|---|
| D-0148 | `.venv`를 찌꺼기로 셌다 |
| D-0150 | 환경 의존 오류를 래칫에 넣었다 |
| **D-0151** | **합계만 박아 어느 부류인지 못 봤다** |

셋 다 **세는 것이 성긴 탓**이고, 성긴 수는 그 수를 보고 한 판단까지 성기게 만든다.
**고칠 때마다 한 칸씩 더 촘촘해졌다.**

- **결과**:
  - `PINNED`이 부류별 표다. `--update`가 정렬해 다시 쓴다.
  - 어긋난 부류의 **실제 줄을 찍는다.**
  - 검사 3건 추가.

### 남기는 것

- **`assignment` 한 건이 왜 기기에서만 나는지 모른다.** 다음 `make check`가
  그 줄을 찍어 주면 거기서 판단한다. **추측해서 미리 고치지 않는다** (GR-0.5).
- **`--allow-growth`가 부류별로도 필요할 수 있다.** 지금은 아무 부류나 늘면 막는다.

재현
    python3 tools/check_test_types.py

강제자  `core/tests/unit/test_test_types.py`

## D-0152. 배선이 돌았다 — 실측 탐침을 세운다

> **갱신됨 — D-0154.** 이 탐침이 20곡을 읽었고 **분석이 안 선다는 것**을 냈다.

> **갱신됨 — D-0153.** 이 탐침이 **첫 실행에서 빈손이었다.** D-0069가 도구에는 안
> 걸려 있어 `core/var/ingest`를 보고 있었다.

- **갱신**: D-0151 — `assignment` 한 건의 자리가 드러났고 고쳤다.

- **배경**: `ingest onsets --limit 20`이 돌았다. **20곡 · 홉 0.01초 · 실패 0.**
  D-0145의 배선이 실물에서 처음 섰다.

### 표가 한 판에 끝냈다

D-0151이 어긋난 부류의 줄까지 찍게 했고 **다음 실행에서 바로 나왔다.**

    tests/unit/test_bge_m3_lyrics_encoder.py:130: error: Incompatible types in
    assignment (expression has type "SimpleNamespace", variable has type Module)

`transformers`가 깔린 기기에서만 실제 타입이 보인다. **`type: ignore`를 달면 그쪽은
사라지고 깔리지 않은 쪽은 `unused-ignore`가 되는데 그것은 이미 안 세는 부류다**
(D-0150). **양쪽이 66으로 맞는다.**

D-0148 → D-0150 → D-0151 → 여기까지 **네 판에 걸쳐 세는 것을 촘촘하게 만들었고,
마지막 한 건이 한 판에 끝났다.**

### 탐침은 판정하지 않는다

`tools/probe_onsets.py`가 곡별 빠르기 · 격차 · 배수 격차 · 박 안 위상을 낸다.
**분포를 낼 뿐이며 무엇을 제품에 쓸지는 보고 나서 결정 기록으로 정한다** — 탐침이
판정하면 그 자리에서 값이 생긴다 (D-0058).

`probe_chord_rhythm`과 같은 모양이다. **정본은 도메인 서비스 하나이고 탐침은 그것을
부른다** (D-0123).

### 볼 것 넷

| | 무엇을 말해주나 |
|---|---|
| 빠르기 분포 | **`--tempo` 기본값 96이 얼마나 틀렸는가** |
| 격차 | 낮으면 박을 못 고른 것이다 |
| 배수 격차 | 낮으면 **사람도 갈릴 자리다** (D-0054) |
| 박 안 위상 | **반주 리듬의 재료다.** 고르면 정박에 안 몰린다는 뜻이다 |

- **결과**:
  - `tools/probe_onsets.py`.
  - `test_bge_m3_lyrics_encoder.py:130`에 `type: ignore`와 사유.

### 남기는 것

- **아직 20곡이다.** 1004곡 배치가 남았고, 20곡의 분포가 전체를 대표한다는 근거는
  없다.
- **박의 원점은 여전히 모른다** (D-0143). 위상 분포의 *모양*만 뜻이 있다.
- **합성에 없던 것이 실측에 있다** — 리버브 · 스윙 · 박자 변화. 탐침이 그것을
  어떻게 드러낼지는 보고 나서 안다.

재현
    cd core
    uv run python ../tools/probe_onsets.py --out var/ingest

강제자 없음 — 사유: 탐침이며 판정하지 않는다. 고정할 동작이 없다

## D-0153. 탐침이 빈손으로 돌아왔다 — D-0069가 도구에는 안 걸려 있었다

- **갱신**: D-0152 — 그 탐침이 첫 실행에서 아무것도 못 찾았다.

- **배경**: `ingest onsets`가 20곡을 `var/ingest/keys-0.01s.onsets`에 썼는데
  **탐침이 "포락선 폴더가 없다"고 했다.**

### 같은 `var/ingest`가 두 곳을 가리켰다

둘 다 `core/`에서 돌렸다.

| | `--out var/ingest`가 푼 곳 |
|---|---|
| `ingest onsets` (CLI) | `<저장소>/var/ingest` — **`resolve_path`가 푼다** (D-0069) |
| `probe_onsets` (도구) | `<저장소>/core/var/ingest` — **현재 디렉터리 기준** |

**D-0069는 CLI 인자에만 걸려 있었다.** `test_cli_contracts`가 `hathor.cli`의 파서를
훑어 `type=resolve_path`를 요구하는데 **`tools/`는 그 검사 밖이었다.**

D-0146이 검사마다 빼 둔 나무를 훑은 것과 **같은 부류이고 이번에는 계약 쪽이다.**

### 셋이 같았다

전수로 보니 경로 인자를 받는 도구가 넷이고 그중 **셋이 현재 디렉터리 기준**이었다.
`lyrics_exclusion_probe` · `lyrics_language_profile`은 저장소 루트에서 돌리는 것이
관행이라 **지금까지 맞았을 뿐이다.** `sync_artifacts`만 루트를 쓰고 있었다.

- **결과**:
  - 셋이 `ROOT` 기준으로 푼다. 절대 경로는 그대로 쓴다.
  - `test_cli_contracts`가 **`tools/`도 본다.** argparse를 실행 없이 들여다볼 수
    없어 **본문에 `ROOT`가 있는지로 본다** — 거칠지만 이 부류를 잡는다.

### 왜 조용했나

**빈손이 오류처럼 안 보인다.** 탐침은 *"폴더가 없다"*고 정확히 말했고 그 말이
맞았다 — **다른 폴더를 보고 있었다는 것만 안 말했다.** 경로를 함께 찍었으면 한눈에
보였을 것이고, 그래서 이제 폴더 이름을 첫 줄에 찍는다.

### 남기는 것

- **검사가 거칠다.** `ROOT`라는 글자가 있는지만 본다. 경로 인자를 받으면서 `ROOT`를
  다른 용도로 쓰는 도구가 생기면 통과한다. **더 촘촘하게 하려면 도구마다
  `build_parser()`를 노출해야 하고 그것은 열여섯 파일을 고치는 일이다.**
- **20곡 실측은 아직 못 봤다.** 탐침이 이제 제자리를 보므로 다음 판에 나온다.

재현
    cd core
    uv run python ../tools/probe_onsets.py

강제자  `core/tests/unit/test_cli_contracts.py`

## D-0154. 20곡 실측이 전곡 배치를 막았다 — 분석이 안 선다

> **갱신됨 — D-0161.** *"빠르기 중앙 69.9는 가요 코퍼스에서 비정상"*이 **틀렸다.**
> 20곡이 전부 10CM이었고 어쿠스틱 발라드에서 70대는 이상하지 않다.

> **갱신됨 — D-0155.** 짐작한 원인(드리프트)이 **틀렸다.** 추정은 잘 되고 있었고
> 연속 에너지가 위상을 뭉갰다.

- **갱신**: D-0143 · D-0144 — 합성에서 통한 것이 실측에서 안 통한다.

- **배경**: `ingest onsets --limit 20`의 산출물을 탐침으로 읽었다.

### 숫자 넷이 같은 말을 한다

| | 실측 | 뜻 |
|---|---|---|
| 박 안 위상 (평균) | `0.257 · 0.247 · 0.247 · 0.250` | **완전 균등** |
| 빠르기 중앙 | **69.9 BPM** | 가요 코퍼스에서 비정상 |
| 배수 격차 `< 0.10` | **12 / 20 (60%)** | 과반이 배수 모호 |
| 격차 중앙 | 0.02 | 1등과 2등 봉우리가 거의 같다 |

**위상 균등이 결정적이다.** D-0143이 합성에서 이 모양을 봤을 때가 **주기 오차로
위상이 뭉개진** 그 버그였다. 3~5분 곡은 400박이 넘고 **주기가 0.1%만 틀려도 끝에서
0.4박이 밀린다** — 합성 128박의 세 배 규모다.

### 합성이 못 담은 것

D-0143이 *"합성에는 리버브도 스윙도 박자 변화도 없다"*고 남겼다. **그 남긴 것이
그대로 값을 냈다.** 합성 12판은 빠르기가 고정이었고 실제 곡은 아니다.

**합성이 관문이라는 것은 맞았고, 관문을 지났다고 통과한 것이 아니라는 것도 맞았다.**

### 전곡 배치를 어떻게 할 것인가

- **후보**:
  | 안 | 판정 |
  |---|---|
  | (1) **포락선만 전곡 뽑고 분석은 보류** | **채택** |
  | (2) 전곡 뽑고 분석까지 돌린다 | **기각.** 못 쓰는 판정 1004개가 생긴다 |
  | (3) 분석이 설 때까지 추출도 멈춘다 | **기각.** 아래 |

- **선택**: **(1).** **포락선은 원자료이고 분석은 나중에 다시 돌린다.** 저장소가
  분리돼 있으므로(`.onsets`는 포락선만 담는다) 추출이 낭비가 아니다. 디코딩이 가장
  비싼 단계이고 그것만 한 번 해 두면 된다.

### 무엇이 나쁜지 아직 모른다

**포락선이 나쁜 것과 추정이 나쁜 것은 다르다.** 가르는 진단을 넣었다.

    uv run python ../tools/probe_onsets.py --diagnose 0

30초 구간마다 따로 재서 **값이 고르면 추정은 되고 위상만 밀린 것**이고
**들쭉날쭉하면 포락선이 나쁜 것**이다. 합성으로 확인했다 — 빠르기 고정 곡은
표준편차 **0.00**, 8% 흔들리는 곡은 **6.26**이었다.

- **결과**:
  - `probe_onsets --diagnose`. 포락선 선명도 · 곡 전체 추정 · 구간별 분포.
  - **전곡 배치는 포락선까지만.** PLAN §1에 적었다.

### 남기는 것

- **위상을 곡 전체로 재는 방법이 틀렸을 가능성이 크다.** 주기 하나로 나눗셈하는
  대신 박을 따라가야(beat tracking) 할 수 있다. **그것은 새 설계이며 진단 결과를
  보고 정한다.**
- **빠르기 중앙 69.9가 절반 오류인지 코퍼스 성질인지 모른다.** 발라드가 많으면
  70대가 이상하지 않다. **20곡으로는 못 가른다.**

재현
    cd core
    uv run python ../tools/probe_onsets.py --diagnose 0

강제자 없음 — 사유: 실측 판정이며 고정할 동작이 없다

## D-0155. 위상이 평평했던 것은 드리프트가 아니라 바닥이었다

> **갱신됨 — D-0156.** 이 고침이 **실측에서 안 통했다.** 바닥을 빼도 잔물결이
> 남았고 봉우리가 박보다 16.7배 촘촘했다.

- **갱신**: D-0154 — 그 결정이 짐작한 원인이 틀렸다.

- **배경**: `--diagnose 0`을 돌렸다. **진단이 짐작을 뒤집었다.**

### 추정은 아주 잘 되고 있었다

    30초 구간별 · 7구간
      5% 68.70 · 25% 68.88 · 중앙 68.95 · 75% 69.10 · 95% 179.12
      표준편차 24.12BPM

**표준편차 24.12는 오해다.** 일곱 중 **여섯이 68.70~69.10 안에 모여 있고**(폭
0.4BPM) 하나만 179로 튀었다 — 간주나 무박 구간일 것이다. **곡 전체 추정 68.91과도
0.04BPM 차이다.**

D-0154는 *"주기가 0.1%만 틀려도 끝에서 0.4박이 밀린다"*고 짐작했는데 **실측 오차는
0.06%이고 251박에서 0.15박이다. 그것으로는 안 뭉개진다.**

### 원인은 연속 에너지였다

합성에 바닥을 넣으니 그대로 재현됐다.

| 바닥 | 박 안 위상 |
|---|---|
| 없음 | `0.675 · 0.000 · 0.000 · 0.325` |
| 0.2 | `0.192 · 0.307 · 0.194 · 0.307` |

**실제 곡에는 노래와 지속음이 연속 에너지를 깔아 둔다.** `phase_profile`이 평균만
빼서 그 바닥이 **모든 위상에 고르게 들어갔다.**

**발음은 봉우리지 에너지가 아니다.**

- **후보**: 무엇을 셀 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **이웃보다 높은 칸만 센다** | **채택** |
  | (2) 문턱을 둬서 낮은 칸을 버린다 | **기각.** 문턱이 값이다 (D-0058) |
  | (3) 중앙값을 빼고 그대로 센다 | **기각.** 바닥이 줄 뿐 사라지지 않는다 |

- **선택**: **(1).** 문턱도 창도 없고 **중앙값 위 높이를 무게로 쓴다.**
  바닥 0.05에서 최대 위상이 `0.765`로 살아났다.

### 자기상관은 안 고쳤다

봉우리로 돌려도 **배수 오류는 안 고쳐진다** — 120BPM·바닥 0.2에서 원본도 봉우리도
60을 골랐다. 96과 140은 둘 다 맞는다. **120은 60이 정확한 半배수라 진짜로 모호하며
`octave_margin`이 이미 신고한다** (D-0143).

**안 고쳐지는 것을 고친 척하지 않는다.**

- **결과**:
  - `onset.peaks`. `phase_profile`이 봉우리만 센다.
  - 검사 5건. **바닥이 있어도 위상이 안 뭉개지는 것**을 고정했다.

### 남기는 것

## D-0164. 예측은 맞았으나 짝지은 비교가 아니었다

> **갱신됨 — D-0165.** 짝지어 보니 **0.282 → 0.310이 곡 구성의 몫이었다.**

- **배경**: 홉 0.005로 39곡을 다시 뽑았다.

### 예측은 약하게 맞았다

| | 홉 0.01 | 홉 0.005 |
|---|---|---|
| 빠른 무리 집중 중앙 | **0.282** | **0.310** |
| 그 무리의 고른 곡 | 9 / 10 | **8 / 9** |

## D-0165. 예측이 틀렸다 — 그리고 박이 격자에 흔들린다

> **갱신됨 — D-0166.** 우회로를 찾다가 **없다는 것**을 쟀다. 간격도 격자 인공물이며
> 척도를 고르는 문제가 어디에도 남는다.

- **갱신**: D-0163 · D-0164 — 사전 등록 예측을 **기각한다.**

- **배경**: `--like 0.01`로 같은 39곡을 홉 0.005에서 다시 뽑아 짝지어 견줬다.

### 사전 등록 예측을 기각한다

D-0163이 *"칸 30~50이던 무리의 집중도 중앙이 0.282에서 오른다"*고 적었다.

| | 값 |
|---|---|
| 짝지은 집중도 차이 (0.005 − 0.01) | **−0.0139** · 중앙 −0.008 |
| t | **−1.32** |

| 빠른 무리(BPM ≥ 140) 중앙 | 0.276 → **0.267** |

**올라야 할 것이 내려갔다.** 칸을 두 배로 해도 집중도는 안 오른다 —
**해상도가 원인이 아니다.**

D-0164가 본 0.282 → 0.310은 **곡 구성이 바뀐 몫이었다.** 짝지으니 사라졌다.
**짝짓지 않은 비교가 얼마나 쉽게 속이는지**를 두 판 만에 다시 봤다 (D-0113).

### 더 나쁜 것이 나왔다

홉만 바꿨는데 **박 추정이 통째로 바뀐 곡이 다섯이다.**

| 곡 | 0.01 | 0.005 | |

| 10CM-pet | 70.6 | 105.8 | 1.50배 |

**박은 곡의 성질이지 격자의 성질이 아니다.** D-0103이 *"창 길이가 그 값을 정한다"*며
대각선을 버린 자리와 **같은 부류이며, 이번에는 박이 그렇다.**

자기상관 봉우리 고르기가 **격자에 좌우된다.** 배수 격차가 낮은 곡에서 어느 봉우리가
1등이 되는지를 홉이 뒤집는다 — D-0143이 *"결함이 아니라 성질"*로 둔 배수 모호성이
**성질이 아니라 불안정이었다.**

- **결과**:
  - `probe_onsets --against`가 **두 홉을 같은 곡끼리 견준다.** 손으로 한 대조를
    도구로 굳혔다 — 다음 판에는 재현된다.
  - **O-47 등재.** 박 추정이 격자에 흔들린다.

### 남기는 것

- **고치는 방법이 없다.** 자기상관을 바꾸는 안은 전부 새 값을 부른다. **두 홉이

## D-0167. 반감점을 온셋에 옮기려 했고 두 번 다 실패했다

> **갱신됨 — D-0170.** 이 결정이 짚은 다음 설계에서 **절반이 틀렸다.** 대역별
> *선속*은 곡선이 거꾸로 서고, 크기 스펙트럼이라야 반감점이 옮겨온다.

- **갱신**: D-0166 — 그 결정이 내놓은 셋 중 **둘째를 골랐고 첫 시도가 졌다.**

- **배경**: O-47은 박이 격자에 흔들리는 것이다. **이 저장소에 이미 같은 문제를 푼
  장치가 있다** — D-0103이 *"창 길이가 대각선을 정한다"*며 대각선을 버리고 세운
  **반감점**이고, 그것이 O-37을 닫았다.

  온셋에 옮겼다.

### 첫 번째 — 시간 집중도의 반감점

묶음 안에서 에너지가 한 자리에 몰린 정도(`max / sum`)가 절반 내려오는 묶음 길이.

| 참 BPM | 60 | 96 | 120 | 150 | 190 |
|---|---|---|---|---|---|
| 발음 간격(초) | 0.0368 | 0.0366 | 0.0367 | 0.0374 | 0.0368 |

**빠르기와 무관하게 0.037초로 고정됐다.** 그리고 홉을 반으로 줄이니 값도 반이
됐다(비 0.48). **격자 무관이 아니라 격자 그 자체를 재고 있었다.**

### 두 번째 — 균등 대비 상대 집중도

`묶음 × 집중도`가 포화하는 값이 간격이어야 한다고 봤다.

| | 박(칸) | 포화 |
|---|---|---|
| 120BPM 홉 0.01 | 50 | **7.7칸 = 0.077초** |
| 60BPM 홉 0.01 | 100 | **9.2칸 = 0.092초** |
| 190BPM 홉 0.01 | 32 | **6.4칸 = 0.064초** |

**포화값이 박이 아니라 평활 창 폭(70ms)에 붙어 있다.**

### 왜 안 되는지가 분명해졌다

**잡음 바닥이 합을 지배한다.** 묶음의 `sum`이 발음이 아니라 바닥으로 채워지므로
`max / sum`이 **간격이 아니라 신호대잡음비**를 잰다. 그래서 빠르기를 바꿔도 안
움직이고 평활 창을 바꾸면 움직인다.

**크로마에는 이 문제가 없다.** 크로마는 **프레임마다 12칸 분포**이고 프레임별로
정규화되므로 **잡음이 질량을 안 더한다.** 반감점은 그 성질에 기대고 있었고,
1차원 포락선에는 그 성질이 없다.

  | 안 | 판정 |
  |---|---|
  | (1) **지우고 기록에 남긴다** | **채택** |
  | (2) 코드에 남겨 둔다 | **기각.** 안 되는 도구가 서 있으면 다음 사람이 쓴다 |

- **선택**: **(1).** D-0104가 기각한 후보들을 코드가 아니라 기록에 남긴 것과 같다.

### 다음 설계가 보인다

**분포를 만들면 된다.** 스펙트럼 선속을 **대역별로** 뽑으면 프레임마다 분포가 되고
크로마와 같은 성질을 얻는다 — 프레임별 정규화가 서고, 잡음이 질량을 안 더한다.

**그러면 반감점이 그대로 옮겨온다.** 다만 **추출을 다시 해야 한다** — 지금 산출물은
1차원이다.

## D-0169. 창을 홉에서 떼어낸다 — 보고 격자가 재는 대상을 바꾸고 있었다

> **갱신됨 — D-0171.** 사전 등록 예측이 **통과했다.** 박 뒤집힘이 4 / 39에서
> **1 / 39**로 줄었다.

- **갱신**: D-0144 — 그 결정이 창을 홉의 네 배로 묶었다.

- **배경**: O-47은 박이 격자에 흔들리는 것이다. D-0167이 다음 설계로 대역별 분포를
  짚었고, 그것을 세우려다 **더 앞의 것**이 나왔다.

### 창이 홉을 따라다녔다

`FRAME_RATIO = 4`가 분석 창을 홉의 네 배로 잡는다. D-0144의 근거는 *"밖에서 오는
값은 홉 하나뿐"*이었고 **그 자체로는 옳다** — 창을 따로 고르면 값이 둘이 되고 둘 다
맞출 수 있게 된다.

**그런데 창은 주파수 해상도를 정한다.** 홉 0.01에서 창 0.04초이고 0.005에서 0.02초다.
**보고 격자를 바꿨을 뿐인데 스펙트럼이 통째로 달라진다.**

실측이 아니라 구조로 드러났다 — 옥타브 대역을 세니 **홉 0.01에서 9개, 0.005에서
8개**가 나왔다. 창이 짧아져 낮은 대역에 빈이 안 남는다. **대역 수가 다르면 두 홉의
뾰족함을 나란히 놓을 수 없다.**

D-0103이 *"창 길이가 그 값을 정한다"*며 대각선을 버린 것과 **같은 부류이며, 이번에는
스펙트럼 전체가 그렇다.** D-0165가 박 다섯 곡이 뒤집히는 것을 봤을 때 **홉만 바꿨다고
적었는데 창도 함께 바뀌고 있었다.**

- **후보**: 창을 어떻게 할 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **초로 고정한다** | **채택** |
  | (2) 홉의 배수로 둔다 | **기각.** 지금 상태이며 격자가 대상을 바꾼다 |
  | (3) 대역 수를 고정해 창을 거꾸로 구한다 | **기각.** 대역 수가 값이 된다 |

- **선택**: **(1).** `WINDOW_SECONDS = 0.04`.

**새로 고른 값이 아니다.** 기본 홉 0.01에서 `0.01 * 4 = 0.04`이므로 **산출물이 안
바뀐다.** 고른 것은 값이 아니라 **묶여 있던 것을 푼 것**이며, 밖에서 오는 값이 둘이
된 대가로 **홉이 재는 대상을 못 바꾸게** 됐다.

### 사전 등록 예측 — 질 수 있다

**O-47의 박 뒤집힘 다섯 곡 중 일부가 줄어든다.** D-0165는 홉만 바꿨다고 적었으나
실제로는 창도 바뀌었고, 창을 고정하면 홉 변경이 **같은 신호를 더 촘촘히 보는 것**이
된다. **안 줄면 원인이 자기상관 쪽이며 창은 무관하다.**

`--like 0.01`로 같은 39곡을 다시 뽑아야 재현된다 — 짝짓지 않으면 또 속는다

## D-0170. 반감점이 옮겨왔다 — 선속이 아니라 크기여야 했다

> **갱신됨 — D-0171.** 격자 무관은 실측에서 확인됐으나(비 1.003) **아래쪽 바닥만

- **갱신**: D-0167 — 그 결정이 짚은 다음 설계를 세웠고 **절반이 틀렸다.**

- **배경**: D-0167이 두 번 실패한 뒤 *"스펙트럼 선속을 대역별로 뽑으면 프레임마다
  분포가 되고 크로마와 같은 성질을 얻는다"*고 적었다. **그대로 해 봤다.**

### 선속으로는 안 된다

`k=1`이 바닥보다 **낮다.** `half_fall`이 다섯 곡 전부 `None`을 냈다.

**발음 사이 프레임이 비어 있기 때문이다.** 선속은 사건에서만 값이 서고 그 사이는
잡음뿐인데, 프레임별 정규화가 **그 잡음을 분포로 만든다.** 묶으면 오히려 사건의
분포를 닮아가므로 곡선이 거꾸로 선다.

**D-0167이 원인을 절반만 짚었다.** 크로마가 되는 이유는 *"프레임마다 분포라서"*가
아니라 **"프레임마다 질량이 있어서"**다. 선속에는 질량이 없는 프레임이 대부분이다.

### 크기 스펙트럼으로 바꾸니 섰다

대역별 **크기**는 모든 프레임에 질량이 있다. 크로마가 바로 그것이다 — 스펙트럼을
12반음으로 접고 1초 창으로 본 것. **여기서는 옥타브로 접고 0.04초 창으로 본다.**

**새로 고른 것은 접는 격자뿐이고 그것은 옥타브다** — 12반음이 한 옥타브인 것과 같은
부류이며 맞추는 값이 아니다. 개수도 안 고른다: 창이 정한 해상도가 더 못 내려가는
자리에서 끝난다.

- **후보**: 무엇을 대역에 담을 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **크기 스펙트럼** | **채택** |
  | (2) 선속 (D-0167의 안) | **기각.** 곡선이 거꾸로 선다 |
  | (3) 반음 격자 | **기각.** 창 0.04초의 해상도가 25Hz이고 저역 반음은 4Hz다 |

- **선택**: **(1).** `bands()`가 `(프레임, 대역)`을 내고 `event_scale()`이
  `chord_rhythm.measure`를 **그대로 부른다.** 정본은 하나이고 베끼지 않는다.

## D-0173. 사건 길이는 있는 것인데 쓸 곳이 없다 — O-47을 닫고 보관한다

- **갱신**: D-0172 — 그 결정이 정한 규칙대로 읽었다.

- **배경**: `--what`을 39곡에 돌렸고, 스템 교란을 가르려고 `.series`에 있는
  **여섯 스템 전부**와 견줬다.

### 시간 순서에서 온다

    프레임 순서를 뒤섞으면
      짝지은 차이 평균 +1.162초 · 중앙 +0.689
      실측이 큰 곡 39 / 39 · t +6.12

**한 곡도 안 졌다.** 잡음이면 이렇게 안 나온다. O-37이 크로마에서 본 것과 같은
모양이다 (D-0123).

### 화성 리듬이 아니다 — 여섯 스템 전부

| 스템 | 순위상관 | 중앙(초) |
|---|---|---|
| `bass` | **+0.312** | 3.87 |
| `mix` | +0.269 | 3.62 |
| `other+bass+vocals` | +0.190 | 3.66 |
| `vocals` | +0.147 | 3.92 |
| `other` | +0.130 | 3.64 |
| `other+bass` | +0.098 | 3.79 |

**`mix`가 판정자다.** 대역과 오디오가 통째로 겹치므로 D-0099대로 **상관이 부풀려지는
쪽**인데 +0.269다. 부풀린 값이 그것이면 참값은 더 낮다.

D-0172가 `other` 하나로 재고 *"스템 탓일 수 있다"*고 남겼는데 **아니었다.**

눈금도 다르다 — 사건 길이 중앙 **0.71초**, 화성 리듬 중앙 **3.6~3.9초**다.

### `bass`의 +0.312를 안 읽는다

구간 밖이지만 **0.5 미만이고 비교를 여섯 번 했다.** 95% 구간을 여섯 번 쓰면 적어도
하나가 헛나올 확률이 **26%**이고, D-0172가 합성 세 판에서 한 번 `+0.365`를 봤다.

그리고 **`other+bass`가 +0.098로 오히려 낮다.** `bass` 성분이 신호라면 섞어도
남아야 한다. 안 남으므로 헛것으로 읽는다.

### 박도 아니다

순위상관 **-0.097**이다. 다만 **중앙값은 0.71초 대 0.67초로 거의 같다** — 전체
눈금은 박과 같은 급인데 곡마다는 따로 논다. **설명하지 못한다** (GR-0.5).

### 쓸 곳이 없다

`apart`를 값 없이 얻으려고 만들었는데 **14 / 39가 박보다 길다.** 5.168초짜리
`apart`는 곡 전체에서 봉우리를 스무 개쯤 남긴다 (D-0172).

- **후보**: 이 지표를 어떻게 할 것인가.
  | 안 | 판정 |
  |---|---|
  | (1) **보관하고 재개 조건을 건다** | **채택** |
  | (2) 지운다 | **기각.** 아래 |
  | (3) 무엇인지 더 판다 | **기각.** 아래 |
  | (4) 제품에 넣는다 | **기각.** 소비자가 없다. GR-6.5가 막는 자리다 |

- **선택**: **(1).**

**(2)를 기각한 이유**: D-0167이 지운 함수 셋은 **작동을 안 했다** — 빠르기와 무관하게
0.037초로 고정됐고 홉을 따라 움직였다. 이것은 39 / 39를 재고, 격자 무관이며(비
0.998), 시간 순서에서 오고(t +6.12), **기존 두 축 어디와도 안 겹친다.** 다른 부류다.

**(3)을 기각한 이유**: 무엇인지 물으려면 후보가 있어야 하는데 지금 있는 것은
*"큰 값이 발라드에 몰린다"*는 눈대중뿐이다. **라벨이 없다** — O-19가 구간에 절·후렴
라벨이 없어 막힌 그 자리이고, O-22가 조성에서 겪은 것과 같다. **후보 없이 상관을
더 뽑으면 낚시가 된다.** 비지도의 한계이며 사용자도 같은 판단이었다.

### O-47을 닫는다

**답이 나왔다.** 박이 격자에 흔들린 것은 **창이 홉에 묶여 있어서**였고(D-0169),
고치니 뒤집힘이 **4 / 39에서 1 / 39**로 줄었다(D-0171). 남은 한 곡은 배수 격차
0.021로 D-0143이 말한 *"사람도 갈릴 자리"*에 가깝다.

**O-46은 안 열렸다.** `apart`를 값 없이 얻는 길은 여전히 없다 — D-0166이 적은
순환이 그대로다.

- **결과**:

  - **O-48 등재** — 사건 길이의 쓸 곳이 없다. 재개 조건을 함께 적었다.
  - `event_scale`·`bands`·`bundle_grid`를 **남긴다.** 산출물도 곡마다 붙어 있다.
